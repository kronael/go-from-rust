## 13:10 2026-09-15

- Released and deployed v0.7.0. `TODO.md` and `BUGS.md` are both empty.
- Built the SIMD lesson the owner chose: concept lesson, plain Go executed.
  The honest framing turned out to be the interesting one. Rust's portable
  SIMD is `E0658` on stable 1.97 and Go's `simd` package needs
  `GOEXPERIMENT=simd`, so neither language gives you portable vectors by
  default. That is the mapping, not a Go shortcoming.
- Wrote the vector version into a comment, but checked it first against the
  real package rather than sketching plausible API calls: it compiles under
  `GOEXPERIMENT=simd` on go1.27.1 and returns the same 190 as the scalar sum,
  at width 8 on this machine. Reading `src/simd/doc.go` gave the actual names
  (`LoadFloat32s`, `LoadFloat32sPart`, `Store`, `Len`), which I would have
  guessed wrong.
- Two real differences from Rust came out of that reading: `Len` is a run-time
  value rather than a const generic like `f32x4`, so one binary adapts to the
  machine, and there is no `unsafe` block because the package emulates in pure
  Go where the hardware is absent.
- The lesson prints that it computed without simd. That is the new contract
  rule applied to the one lesson most tempted to imply otherwise.
